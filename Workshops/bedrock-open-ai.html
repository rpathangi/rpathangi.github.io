Workshop

Bedrock OpenAI Agent

Build a Lab Manual Q&A agent using AI-DLC, Kiro, and OpenAI open-weight models on Amazon Bedrock.

The Problem

Lab scientists spend significant time searching instrument manuals, SOPs, and protocol documents for specific procedures, troubleshooting steps, or safety information. An AI agent that answers these questions instantly — grounded in actual documentation — saves hours per week.

The Approach

You'll use AI-DLC (AI-Driven Development Life Cycle) inside Kiro to build this agent through a structured workflow:

  1. Describe what you want in plain English.
  2. AI-DLC asks clarifying questions and produces a design.
  3. You approve → AI-DLC generates the code.
  4. You review, test, and iterate.

The reasoning engine behind the agent is OpenAI gpt-oss-120b running on Amazon Bedrock.

Follow the steps in order — each one builds on the previous. Every command below has a macOS / Linux and a Windows (PowerShell) tab; pick the one for your machine.

5

Verify Amazon Bedrock Access

  1. Open the Amazon Bedrock console.
  2. Set the region to US West (Oregon) / us-west-2.
  3. Open Playgrounds → Chat.
  4. Select OpenAI → gpt-oss-120b.
  5. Submit a test question.

For CLI verification:

aws sts get-caller-identity --profile workshop
aws sts get-caller-identity --profile workshop

Common Errors

  • "You don't have access to this model" — Wait 30–60 seconds and confirm the workshop event is active.
  • "Region not available" — Set the region to us-west-2 in the console dropdown.
  • InvalidClientTokenId — Recheck the access key, secret key, and session token in ~/.aws/credentials (%USERPROFILE%\.aws\credentials on Windows).
  • AccessDeniedException — The workshop profile may not have Bedrock permissions. Verify the event is still running.

Troubleshooting

  • Python version below 3.10 — Install Python 3.10+ from python.org before continuing.
  • "No matching distribution" — Confirm your Python version: python3 --version (python --version on Windows).
  • Permission errors — Ensure the virtual environment is activated (you should see (.venv) in your prompt).
  • Windows: "running scripts is disabled" — Allow the activation script for the current session: Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
7

Install AI-DLC Rules

curl -sL https://api.github.com/repos/awslabs/aidlc-workflows/releases/latest \
  | grep -o '"browser_download_url": *"[^"]*"' \
  | head -1 \
  | cut -d'"' -f4 \
  | xargs curl -sL -o /tmp/aidlc-rules.zip

unzip -o /tmp/aidlc-rules.zip -d /tmp/aidlc-release

mkdir -p .kiro/steering

cp -R /tmp/aidlc-release/aidlc-rules/aws-aidlc-rules \
  .kiro/steering/

cp -R /tmp/aidlc-release/aidlc-rules/aws-aidlc-rule-details \
  .kiro/

rm -rf /tmp/aidlc-rules.zip /tmp/aidlc-release
$release = Invoke-RestMethod https://api.github.com/repos/awslabs/aidlc-workflows/releases/latest
$asset = $release.assets[0].browser_download_url
Invoke-WebRequest -Uri $asset -OutFile "$env:TEMP\aidlc-rules.zip"

Expand-Archive -Path "$env:TEMP\aidlc-rules.zip" -DestinationPath "$env:TEMP\aidlc-release" -Force

New-Item -ItemType Directory -Force -Path .kiro\steering | Out-Null

Copy-Item -Recurse -Force "$env:TEMP\aidlc-release\aidlc-rules\aws-aidlc-rules" .kiro\steering\

Copy-Item -Recurse -Force "$env:TEMP\aidlc-release\aidlc-rules\aws-aidlc-rule-details" .kiro\

Remove-Item -Recurse -Force "$env:TEMP\aidlc-rules.zip", "$env:TEMP\aidlc-release"

7.1

Start AI-DLC

In Kiro's chat, paste this prompt:

Kiro chat prompt
Using AI-DLC, build a Lab Manual Q&A agent using the Strands Agents SDK with OpenAI gpt-oss-120b on Amazon Bedrock (us-west-2).

The agent should:
- Answer questions about lab instrument operation and maintenance
- Provide troubleshooting guidance for common instrument issues
- Look up safety and handling procedures
- Reference specific manual sections in responses
- Use tools for each capability (manual lookup, troubleshooting, safety info)
- Use mock manual data (simulating a centrifuge, spectrophotometer, and PCR thermocycler)
- Run as a Python script for local testing

Keep it simple — single file, no database, mock data is fine.
