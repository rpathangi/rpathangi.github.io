Challenge

Query RDS PostgreSQL with Amazon Quick and the AWS MCP Server

Goal: Follow these steps in order to connect Amazon Quick (as a Model Context Protocol client) to the AWS MCP Server and run SQL against an Amazon RDS for PostgreSQL database from a Quick agent - access governed by IAM and audited in CloudTrail. Steps are numbered 1–13; complete each before moving on.

Before you start - have these ready

  • An Amazon Quick Professional subscription, and a Quick user with Author (or higher) permissions.
  • An Amazon RDS for PostgreSQL or Aurora PostgreSQL database, plus its endpoint, port (5432), and database name.
  • The AWS CLI v2 configured (aws --version) with permission to manage IAM, Secrets Manager, and RDS.
  • Node.js 18+ (for the MCP Inspector check in Step 6) and psql or any SQL client to run Step 1.
  • Set your working region once so every command below is consistent:
bash
export AWS_REGION=us-west-2
export ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
echo "Region=$AWS_REGION  Account=$ACCOUNT_ID"
Part 1

Prepare Amazon RDS for PostgreSQL

Create a read-only login, store its credentials, and grant the exact AWS permissions the agent needs.

1

Create a read-only database role

Connect to your database with an admin user and create a login that can only read data. This limits what any agent query can do.

sql
-- run against your PostgreSQL database (e.g. via psql)
CREATE ROLE app_ro LOGIN PASSWORD 'CHANGE_ME_STRONG';
GRANT CONNECT ON DATABASE appdb TO app_ro;
GRANT USAGE ON SCHEMA public TO app_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_ro;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO app_ro;

Replace appdb with your database name. Verify you can log in as app_ro before continuing.

2

Store the credentials in AWS Secrets Manager

Create a secret so nothing is hard-coded. Use your real host and database name:

bash
aws secretsmanager create-secret \
  --name rds-postgres \
  --secret-string '{"host":"mydb.abc123.us-west-2.rds.amazonaws.com","port":5432,"dbname":"appdb","username":"app_ro","password":"CHANGE_ME_STRONG"}'

Copy the returned ARN (looks like arn:aws:secretsmanager:us-west-2:<account>:secret:rds-postgres-XXXXXX). You'll reference it in Steps 4 and 12.

3

Enable the RDS Data API (Aurora PostgreSQL only)

If you use Aurora PostgreSQL, turn on the HTTP endpoint so SQL can run as an AWS API call:

bash
aws rds modify-db-cluster \
  --db-cluster-identifier my-aurora-postgres \
  --enable-http-endpoint \
  --apply-immediately

Standard RDS for PostgreSQL?

The RDS Data API is an Aurora feature. If you run standard RDS for PostgreSQL, skip this step and use the direct-connection path (Step 13, Path B).

4

Create a least-privilege IAM policy

Save this as quick-mcp-rds-policy.json, replacing the account ID, secret ARN, and cluster ARN with yours:

quick-mcp-rds-policy.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadDbSecret",
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "arn:aws:secretsmanager:us-west-2:123456789012:secret:rds-postgres-*"
    },
    {
      "Sid": "RdsDataApi",
      "Effect": "Allow",
      "Action": ["rds-data:ExecuteStatement", "rds-data:BatchExecuteStatement"],
      "Resource": "arn:aws:rds:us-west-2:123456789012:cluster:my-aurora-postgres"
    }
  ]
}

Create the policy (drop the RdsDataApi statement if you skipped Step 3):

bash
aws iam create-policy \
  --policy-name QuickMcpRdsQuery \
  --policy-document file://quick-mcp-rds-policy.json

You will attach this policy to the IAM identity the AWS MCP Server uses in Step 5.

Part 2

Connect and authorize the AWS MCP Server

The AWS MCP Server is managed and authenticates through your IAM credentials.

5

Get the endpoint and attach the policy

Open the AWS MCP Server guide and follow it to obtain your MCP server endpoint URL and the IAM identity (role) the server uses to execute AWS API calls and sandboxed scripts on your behalf.

  1. Note the endpoint URL - you'll paste it into Amazon Quick in Step 7. Save it for reference:
bash
# Paste the endpoint from the AWS MCP Server guide
export MCP_ENDPOINT="https://<your-aws-mcp-server-endpoint>"
  1. Attach the Step 4 policy to that IAM role so the server can reach your database:
bash
aws iam attach-role-policy \
  --role-name <aws-mcp-server-execution-role> \
  --policy-arn arn:aws:iam::123456789012:policy/QuickMcpRdsQuery

Why IAM here

The AWS MCP Server runs AWS API calls, sandboxed Python, and curated skills using your existing IAM credentials, through a single endpoint with CloudWatch metrics and CloudTrail logging. Documentation search works without authentication - a quick way to confirm the endpoint is reachable in Step 6.

Part 3

Validate the endpoint before Amazon Quick

Confirm the server is protocol-compliant so the Quick integration doesn't fail later.

6

Test the endpoint with the MCP Inspector

The MCP Inspector is a generic MCP client. Use it to connect, list tools, and confirm a SQL/execute capability is present:

bash
npx @modelcontextprotocol/inspector
  1. In the Inspector UI, set Transport to Streamable HTTP (SSE also works; HTTP streaming is preferred).
  2. Enter your MCP_ENDPOINT and any auth the server requires.
  3. Choose Connect, then List Tools. Confirm you can see the tools you intend to call (for example, an AWS API / execute-statement capability).

If the Inspector connects and lists tools, the server is ready for Amazon Quick.

Part 4

Register the MCP integration in Amazon Quick

These are the exact Amazon Quick console steps.

7

Create the integration

  1. Sign in to the Amazon Quick console as a user with Author permissions or higher.
  2. Choose Integrations.
  3. Choose Add (+), then choose Model Context Protocol (MCP).
  4. On the Create integration page, enter a Name, an optional Description, and your MCP server endpoint URL (your MCP_ENDPOINT). Choose Next.
  5. Select the authentication method your server supports (user authentication or service authentication) and enter the required values. If the server supports OAuth Dynamic Client Registration (DCR), the auth step is skipped and credentials are exchanged at sign-in.
  6. Choose Create and continue. Review the discovered tools and data capabilities, then choose Next.
  7. Optionally share the integration with other users, then choose Done.

If integration creation fails on OAuth

Some identity providers block OAuth redirects unless the Amazon Quick callback URI is allow-listed in your OAuth client. Add the redirect URI for your Region, for example:

  • https://us-east-1.quicksight.aws.amazon.com/sn/oauthcallback
  • https://us-west-2.quicksight.aws.amazon.com/sn/oauthcallback
  • https://eu-west-1.quicksight.aws.amazon.com/sn/oauthcallback
  • https://ap-southeast-2.quicksight.aws.amazon.com/sn/oauthcallback

Two limits to design around

Each MCP operation has a fixed 300-second timeout (operations that exceed it fail with HTTP 424) - keep queries fast. Amazon Quick also treats the tool list as static after registration; if the server's tools change, re-authenticate or refresh the integration.

Part 5

Test, then use it in an agent

Verify the tools work, then let an agent run SQL from natural language.

8

Test the action in Amazon Quick

Use the built-in Test APIs section for your new integration to invoke a tool directly and confirm it returns data. A successful test means Amazon Quick can authenticate to the server and call the tool.

9

Build a Chat Agent and connect the integration

  1. In Amazon Quick, create a Chat Agent.
  2. Add the MCP integration you created so the agent can call its tools.
  3. Give the agent instructions, for example: "Use the connected tools to run read-only SQL against the appdb PostgreSQL database and return concise results. Never modify data."
10

Ask questions in natural language

In the agent, try prompts such as:

agent prompts
Show the 10 most recent rows from the orders table.
How many customers signed up in the last 30 days?
What are the top 5 products by revenue this quarter?

The agent turns each request into SQL and runs it through the MCP server using one of the two paths in Step 13.

Part 6

How the query actually runs

Reference for what the tool does under the hood - and how to verify it yourself from the CLI.

11

Path A - Aurora PostgreSQL via the RDS Data API

For Aurora, SQL runs as an AWS API call with no direct connection. Verify from the CLI using your secret and cluster ARNs:

bash
aws rds-data execute-statement \
  --resource-arn "arn:aws:rds:us-west-2:123456789012:cluster:my-aurora-postgres" \
  --secret-arn "arn:aws:secretsmanager:us-west-2:123456789012:secret:rds-postgres-abc123" \
  --database "appdb" \
  --sql "SELECT id, status, created_at FROM orders ORDER BY created_at DESC LIMIT 10;"
12

Path B - standard RDS via a sandboxed script

For standard RDS for PostgreSQL, the tool reads the secret and connects with a driver. The equivalent Python:

python
import json, boto3, psycopg

secret = boto3.client("secretsmanager").get_secret_value(SecretId="rds-postgres")
creds = json.loads(secret["SecretString"])

with psycopg.connect(
    host=creds["host"], port=creds.get("port", 5432),
    dbname=creds["dbname"], user=creds["username"], password=creds["password"],
) as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT id, status, created_at FROM orders ORDER BY created_at DESC LIMIT 10;")
        for row in cur.fetchall():
            print(row)
13

Clean up when you're done

Remove the test integration and any credentials you created:

  1. In the Amazon Quick console, choose Integrations, select the integration, open the Actions (three-dot) menu, and choose Delete integration; confirm.
  2. If you used OAuth, revoke the Amazon Quick client in your authorization server.
  3. Delete AWS test resources you no longer need:
bash
aws iam detach-role-policy --role-name <aws-mcp-server-execution-role> \
  --policy-arn arn:aws:iam::123456789012:policy/QuickMcpRdsQuery
aws iam delete-policy --policy-arn arn:aws:iam::123456789012:policy/QuickMcpRdsQuery
aws secretsmanager delete-secret --secret-id rds-postgres --recovery-window-in-days 7
