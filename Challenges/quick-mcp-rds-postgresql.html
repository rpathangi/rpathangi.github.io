Challenge

Query RDS PostgreSQL with Amazon Quick and the AWS MCP Server

Goal: Connect Amazon Quick (as a Model Context Protocol client) to the AWS MCP Server so a Quick AI agent can run SQL against an Amazon RDS for PostgreSQL database using natural language — with access governed by your existing IAM credentials and every call captured in CloudTrail.

Part 1

Prepare your AWS environment

Set up the database, credentials, and permissions the MCP server will use to reach PostgreSQL.

Prerequisites

  • An Amazon Quick Professional subscription
  • An Amazon Quick user with Author (or higher) permissions to create action connectors
  • An Amazon RDS for PostgreSQL (or Aurora PostgreSQL) database you can reach
  • Permissions to create IAM policies and AWS Secrets Manager secrets
1

Confirm your PostgreSQL database

Note the database endpoint, port (default 5432), and database name. Confirm the network path the MCP server will use is reachable, and that a database user exists with only the privileges the agent needs (prefer read-only for query workloads).

Data API vs direct connection

The RDS Data API (rds-data) lets you run SQL over an AWS API call and is available for Aurora PostgreSQL. For standard RDS for PostgreSQL, connect directly with a driver (for example psycopg) using credentials from Secrets Manager. Both approaches are shown below.

2

Store database credentials in AWS Secrets Manager

Create a secret that holds the connection details so nothing is hard-coded:

bash
aws secretsmanager create-secret \
  --name rds-postgres \
  --secret-string '{"host":"mydb.abc123.us-west-2.rds.amazonaws.com","port":5432,"dbname":"appdb","username":"app_ro","password":"REPLACE_ME"}'
3

Grant least-privilege IAM permissions

The AWS MCP Server executes AWS API calls and sandboxed scripts using your IAM credentials. Attach a policy that allows only what the agent needs — reading the secret, and (for Aurora) the RDS Data API:

json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadDbSecret",
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "arn:aws:secretsmanager:us-west-2:123456789012:secret:rds-postgres-*"
    },
    {
      "Sid": "RdsDataApi",
      "Effect": "Allow",
      "Action": [
        "rds-data:ExecuteStatement",
        "rds-data:BatchExecuteStatement"
      ],
      "Resource": "arn:aws:rds:us-west-2:123456789012:cluster:my-aurora-postgres"
    }
  ]
}

Note

Omit the RdsDataApi statement if you are connecting directly to standard RDS for PostgreSQL rather than using the Aurora Data API.

Part 2

Understand the AWS MCP Server

Know what the managed server exposes before you connect Amazon Quick to it.

4

Review the server's capabilities

The AWS MCP Server is a managed server that gives agents access to AWS through MCP. Key points for this challenge:

  • Agents can search AWS documentation and retrieve service information without authentication.
  • To execute AWS API calls, run Python scripts in a sandbox, or follow curated skills, agents authenticate through your existing IAM credentials.
  • All capabilities are reachable through a single endpoint, with CloudWatch metrics and IAM-based access controls.
  • CloudTrail logs every API call, so database access through the server is auditable.

For this challenge, the agent will use IAM-authenticated capabilities — either the RDS Data API (Aurora) or a sandboxed Python script (standard RDS) — to run SQL.

Part 3

Configure the Amazon Quick MCP integration

Amazon Quick acts as the MCP client and connects to the AWS MCP Server endpoint.

5

Register the MCP integration in Amazon Quick

Signed in as an Author, create an MCP action connector in Amazon Quick and point it at the AWS MCP Server endpoint. Provide the authentication your server requires so Quick can connect on behalf of the user. Amazon Quick discovers the tools the server exposes and makes them available to agents and automations.

How Amazon Quick connects

Amazon Quick supports MCP integrations for action execution and data access. It acts as an MCP client, connects to your MCP server endpoint, discovers the exposed tools, and invokes them using the customer's authentication, authorization, and governance controls. See the integration walkthrough in the Amazon Quick + MCP blog.

6

Build an agent that uses the tools

Create an Amazon Quick agent and give it access to the MCP integration. In the agent's instructions, describe the database and how it should answer — for example, "Use the connected tools to query the appdb PostgreSQL database and return concise, read-only results."

Part 4

Run commands against RDS PostgreSQL

Ask the agent in natural language; it invokes the MCP tools to run the SQL.

7

Ask the agent a question

In the Amazon Quick agent, try prompts such as:

agent prompts
Show the 10 most recent rows from the orders table.
How many customers signed up in the last 30 days?
What are the top 5 products by revenue this quarter?

The agent translates the request into SQL and runs it through the MCP server using one of the paths below.

8

Path A — Aurora PostgreSQL via the RDS Data API

For Aurora PostgreSQL, the agent can run SQL as an AWS API call — no direct database connection required:

bash
aws rds-data execute-statement \
  --resource-arn "arn:aws:rds:us-west-2:123456789012:cluster:my-aurora-postgres" \
  --secret-arn "arn:aws:secretsmanager:us-west-2:123456789012:secret:rds-postgres-abc123" \
  --database "appdb" \
  --sql "SELECT id, status, created_at FROM orders ORDER BY created_at DESC LIMIT 10;"
9

Path B — standard RDS for PostgreSQL via a sandboxed script

For standard RDS for PostgreSQL, the agent runs a Python script in the sandbox that reads the secret and connects directly:

python
import json
import boto3
import psycopg

secret = boto3.client("secretsmanager").get_secret_value(SecretId="rds-postgres")
creds = json.loads(secret["SecretString"])

with psycopg.connect(
    host=creds["host"],
    port=creds.get("port", 5432),
    dbname=creds["dbname"],
    user=creds["username"],
    password=creds["password"],
) as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT id, status, created_at FROM orders ORDER BY created_at DESC LIMIT 10;")
        for row in cur.fetchall():
            print(row)

Keep access read-only where you can

Use a database role limited to SELECT for query agents, and scope the IAM policy and secret to the specific database. This limits blast radius if a prompt asks for more than intended.
